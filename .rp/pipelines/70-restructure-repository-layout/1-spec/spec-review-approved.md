# Spec Review

## Verdict: approved

## Summary

The spec is complete, consistent, and feasible. I verified every load-bearing claim against the actual repository — the hidden `.agents/` canonical sources, all six mirror symlinks (root `agents`, root `skills/radical-pipelines`, `.claude/skills`, `.pi/skills`, `.pi-extension/skills`, `.pi-extension/agents`), the 17 agent profiles, the dual Pi manifest with `pi.skills[0]` pointing at `.pi-extension/skills`, the single dangling `.agents/...` absolute path at `health-monitoring.md:65`, the 11 `.rp.md` occurrences across the 4 conventions files, the `sync-version.mjs` `TARGET_MANIFESTS` pair, the `.gitignore` entries, the `release:version` `--prefix .pi-extension` step, and the false "root manifest declares the same bundled dependencies directly" sentence at `README.md:139` (the root `package.json` has no `bundledDependencies`). Each maps cleanly to a requirement and acceptance criterion. The spec correctly carries forward all four prompt corrections (singular `skill/` rejected as discovery-breaking, `CLAUDE.md` retained, the bundled-dependencies claim flagged for correction rather than repetition, and `providers/` dropped) and places them in requirements or Out of Scope. The four Open Decisions are genuinely deferred, and — critically — the requirements hold under both OD1 branches without silently assuming one. The acceptance criteria are in Given-When-Then form and testable, with honest, scoped deferral of the empirical Pi/Claude checks to a later phase that has the CLIs available. The spec stays at the WHAT level; the few specific constraints it states (the `skills/<name>/` shape, the version source/target) are externally forced by tool discovery and the existing release tooling, not design choices.

## Notes (non-blocking, for the design phase)

- **OD1 neutrality verified.** I specifically checked that AC1 does not assume Branch A. AC1 says "the separate root conventions pointer ... no longer exist[s]" — under Branch B the merged file stays at the root `.rp.md` path, but the current file there is a *pointer* to per-tool files, which is replaced by merged content; the pointer-qua-pointer is gone either way, so AC1 holds under both branches. Notably the spec is more careful than `spec-research.md` here: the research's AC1 (line 222) lists "root `.rp.md` (merged)" among items that no longer exist, which would be wrong under Branch B — the spec correctly does **not** carry that forward and never unconditionally asserts deletion of root `.rp.md`. Requirements 5, 6, and 8 and AC6/AC7 likewise hold under both branches.
- **`.pi-extension/README.md` fold-in.** The research treated folding its minor verification-note provenance into the root README as a nice-to-have, not a hard requirement; its absence from the spec is acceptable. Requirement 4's "its supporting files must no longer exist" correctly covers the lockfile, `teams.yaml`, and `README.md` at the WHAT level without enumerating them.
- **OD3 has no hidden dependency.** Requirement 8 and AC7 govern only this repo's own artifacts (`.rp/pipelines/`); the shipped suggested default (`setup.md:52`) is left to OD3 with no requirement silently assuming its resolution.
