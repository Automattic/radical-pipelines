# Code Plan: Make guardrails prose

## Overview

This change redefines a guardrail in the Radical Pipelines skill from "an exact command judged pass/fail by exit code" to **a prose rule an agent must satisfy**, expressed in two kinds — a **command guardrail** (its prose tells the agent to run a command and confirm the check it describes is satisfied) and a **judgment guardrail** (a prose rule the named agent satisfies by its own assessment, with no command). The subject is the skill and agent-profile Markdown itself; there is no runtime, parser, or code — the entire change is a coordinated prose edit across **nine in-scope files**, and every consequence is verified by reading the prose, not by running tests. Per the project authoring rule "the skill is prose, not software — do not write structural tests that assert the content, sections, wording, or ordering of skill or agent files," **no task adds tests**; each task's Acceptance is an observable, readable property of the edited prose. The plan is ordered so the canonical model file (`reference/guardrails.md`) — which every other file points at — is rewritten first (Task 1), then the loader, spawn-time passing block, and setup capture that depend on the model (Tasks 2–4), then the three writers (Task 5), and finally the two reviewers (Task 6). Tasks 5 and 6 also strip the last exit-code phrases and standardize terminology, completing the skill-wide sweep the final acceptance criterion checks.

This change is pure skill/markdown prose.
