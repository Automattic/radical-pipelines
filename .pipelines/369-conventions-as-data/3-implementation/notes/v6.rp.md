# Shop project conventions

## Shared conventions

### Issues

Issues live in GitHub at example/shop, read and written with the `gh` CLI. The canonical reference is the issue number.

### Pipeline slug

`<issue-number>-<short-description>`, lowercase kebab-case, without `_`.

### Artifact storage

`artifacts-in-repo`. The artifact base branch is `main`.

### Worktree folder root

`.worktrees/`

### Commit format

Imperative mood, sentence case. End with the profile name in parentheses.

Example: `Add spec (spec-producer)`

### Agents

#### spec-producer

- model: opus
- subagents: sonnet
- lanes:
  - `demands`, on `opus` — brief: Read the intent for what it demands.
  - `omits`, on `sonnet` — brief: Read the intent for what it leaves out.

#### implementer

- model: opus
- subagents: sonnet

#### reviewer

- lanes, without a brief:
  - `default`, on `opus`; subagents `sonnet`.
  - `second`, on `astra`; subagents `luna`.

### Guardrails

#### tests

- rule: Run `npm test` and confirm it passes.
- agents: implementer, reviewer

### Resources

#### staging environment

- resource: Each agent has its own staging environment `{agent}`, at `https://{agent}.staging.example.com`. Start it with `npm run env:start {agent}` and reset it with `npm run env:reset {agent}`.
- agents: implementer, reviewer

### Lifecycle hooks

#### after-creating-worktree

- **Blocking:** create the staging environment `{agent}` for each agent that will work in the worktree, where `{agent}` is `<pipeline slug>-<profile>[-<lane>]`: run `npm run env:create {agent}`.

#### run-ended

- Remove every staging environment of the pipeline.
