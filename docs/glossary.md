# Glossary

The canonical terms of Radical Pipelines. Terms are used exactly as defined here: no synonyms or alternate notation. [The v4 model](./model.md) explains the design these terms describe.

- **Assignment** — A role's filled template, written by `rp next --apply` before every turn to `<profile>.md` in the assignment folder of the role's worktree. The message that starts a turn only says to read it, and the role rereads it after a compaction and whenever it is unsure of its seat, mode, materials, or rules. It states the command that runs `rp` as the role.
- **Assignment folder** — The folder `git rev-parse --git-path rp/` resolves to in a worktree, inside its private git directory and outside the tree. It holds the assignments of the roles seated there and the diff a reviewer reads on a later turn, and, in the pipeline worktree, the turn record.
- **Artifact** — A file a role owns and the pipeline's state is computed from: `spec.md`, `design-doc.md`, and `notes.md`. Later inputs, threads, and the frontier name them `spec`, `design-doc`, and `implementation`.
- **Artifact storage** — The project convention naming where `.rp.md` and the pipelines folder live — the project's repository or a fork — and the artifact base branch: where pipelines start.
- **Awaiting** — Whose turn an `open` thread is: it awaits its opener when its recipient wrote the last message, and its recipient otherwise.
- **Base branch** — `config.json`'s `base-branch`: the branch a pipeline started from, which it takes updates from — the artifact base branch, or another pipeline's unmerged branch.
- **Blocker** — A role's report that something it was given failed it — its materials, its worktree, or the worktree's environment. The orchestrator repairs it and wakes the role again.
- **Brief** — A lane's direction: what a production lane explores, or what a review lane's reviewer is asked to report, in place of the default.
- **Candidate** — A production lane's version of the spec or the design doc, written in `<phase folder>/lanes/<lane>/`. It is not an artifact: candidates are required inputs only while their artifact is missing.
- **Certification** — `rp`'s record of a landed artifact, candidate, or approval, in `certification/<its path>.json` in the pipeline folder: a pin of each required input and, on an approval, its approved commit. Only `rp land` writes it; no role or orchestrator step touches it.
- **Closure action** — A moment the owner invokes on a pipeline: opening its pull request, merging it, or closing without merging. Each is bracketed by lifecycle hooks.
- **Complete** — A phase whose work is done, every phase below it complete: its artifact fresh, `notes.md` done, with no open thread awaiting its role; for review, every review lane approved with no thread awaiting a reviewer. `rp check --json` lists the complete phases, and `rp land` prints those its landing made complete, which fire `phase-completed`.
- **Considered and not required** — The spec section listing, one line each, the cases its producer examined and left out because no intended use produces them, and the readings of the intent it did not take.
- **Consolidate** — The producer mode that writes the artifact from the candidates: a case or decision every lane reached is kept; one only one lane reached is kept only when intended use is observed to produce its input; where lanes chose differently, the producer decides from the evidence and records the alternative in one line.
- **Consolidated** — An artifact written from candidates.
- **Constraint** — A binding owner ruling, in the intent or a later `0-intent/constraint-<n>.md` with `target` and `origin`. Constraints are owner territory.
- **Disagreement** — A reply that repeats a position without new evidence. About a derived requirement or a design decision, it resolves inside its thread by observation. About what the intent means or demands, either party — the implementer, on a review thread — opens a thread to `owner` about `intent` with status `escalated`, the only status that reaches the owner, its `cites` naming the thread. A question the intent's words leave open is no disagreement: the producer takes the reading the Goal and intended use support and records the other.
- **File grammar** — Every check `rp check` makes of a pipeline file that reads the file alone, never the pipeline configuration. `rp validate` applies it to a role's own files, and `rp thread` to each thread file it writes, so both work in a review lane's tree. `rp pipelines` applies it to each pipeline's intent.
- **Frontier** — What `rp check` says to do next: the first that holds of a malformed file (`malformed`), an escalation (`escalate`), the lowest phase whose role has work (`produce`, `respond`, `consolidate`, or `review`, a production lane's naming its lane), or `complete`.
- **Frontmatter** — The YAML between `---` lines at the top of a file that holds the values `rp` reads: the intent's origins, a later input's `target` and `origin`, `notes.md`'s `status`, and a thread's header. Each line is `<key>: <value>`, the value text on one line; `rp check` reports anything else as malformed.
- **From-intent / derived** — The origin every requirement carries. `from-intent`: the intent states it, and the requirement cites the intent item. `derived`: the producer inferred it, and the requirement cites the input observed in intended use that makes the case material. A derived requirement without an observed input is written as an assumption.
- **Guardrails** — The project convention listing the rules a profile must satisfy — prose it follows, or a check it runs — each an entry naming the profiles it binds. The reviewer evaluates each against the change.
- **Identity** — The first 12 hexadecimal characters of the blob id Git stores for a whole file, so the working tree and a commit agree.
- **Instance name** — A spawned role's name, `<pipeline slug> <profile>[ <lane>]`.
- **Intended use** — A use the intent names, or one that the project's documentation or code shows a consumer making. It is how roles judge whether a case matters: an input an artifact or the code merely admits, or a consumer no source shows, is not intended use.
- **Issue** — The unit of work a pipeline realizes.
- **Landing** — `rp land` for one role's turn: verifying its commits are on its branch, validating the pipeline files they change, bringing a lane's commits onto the pipeline branch, certifying its artifact at its turn commit and every review thread its turn closed `approved` at the commit its reviewer's last heading names, committing, and reporting the phases it completed. A malformed file lands nothing, and the next step wakes its author.
- **Lanes** — The project convention giving the lanes each profile runs — production lanes for `spec-producer` and `design-doc-producer`, review lanes for `reviewer` — and their briefs. A pipeline configuration records the lanes the owner confirmed.
- **Later input** — What the owner brings after the intent: a constraint, a proposal, or a reported failure, each in `0-intent/` with `target` naming the artifacts it targets and `origin` naming where it came from, holding only what the owner gave in the fewest words that carry it. A later input is a required input of every artifact it targets, never of a candidate.
- **Missing** — An artifact whose file is absent. `notes.md` is also missing until its `status` is `done`.
- **Merge-base** — The merge-base of the inspected tip with the base branch: where the net change starts, and what an approval's code is merged with.
- **Mode** — The procedure a role's assignment selects: produce, respond, or consolidate for a producer; implement or respond for the implementer. The reviewer has none: its first turn, its later turns, and a turn that only repairs files it wrote each have their own assignment template.
- **Models** — The project convention giving the model each profile and lane is spawned on, and its subagent model; a lane without its own takes its profile's. A pipeline configuration records the models the owner confirmed.
- **Net change** — The pipeline's change outside the pipelines folder: the diff from its merge-base to its tip, what the reviewer reads.
- **Notes** — `3-implementation/notes.md`, the implementer's resumption file: the inputs it started from, what is done, what remains, the decisions a successor should know, and the approaches that failed. `status: done` in its frontmatter declares the implementation complete.
- **Observed / assumed** — The label on every claim. A claim about current behavior is `observed: <how>`; a claim about what the solution will do is `assumed: <what will confirm it>`, and the implementer verifies it.
- **Orchestrator** — The session running the skill. It triages with the owner, records phase 0, runs each step `rp next` plans, firing its hooks and waking the roles it names, lands their turns with `rp land`, carries disagreements on owner territory to the owner, and opens the pull request. It judges no content and relays no message.
- **Origin** — The source from which something was born: an issue reference, the URL of an external source, a pipeline it starts from or re-attempts, or the thread an owner's answer settles.
- **Owner** — The person running the pipeline; talks only to the orchestrator. As a thread role, `owner` is the party of a thread about `intent`.
- **Owner escalation** — A thread with status `escalated`, opened for a disagreement on what the intent means or demands, or for evidence that every kind of approach fails an intent goal or constraint; its `cites` names that thread or evidence. The run stops; the owner's answer is recorded as a constraint or a proposal, as the owner rules, targeting the disputed artifact, and the thread is closed `answered`.
- **Owner territory** — What the intent means or demands: its Goal, its constraints, and later constraint files. Everything after the intent is chosen by a role and settled between roles.
- **Phase** — One pipeline stage: Intent, Spec, Design doc, Implementation, or Review.
- **Placeholder** — A name in braces, such as `{role}`, in a guardrail's, a resource's, or the commit format's text, or in a lane's brief. `rp next --apply` replaces one that names a pipeline fact or a variable with its value for the role; any other reaches the role as written, with the pipeline facts listed in its assignment, and the role substitutes it.
- **Plan** — What `rp next` prints for the loop's next step, changing nothing: the frontier, the turns to land first, the worktrees and lane branches applying creates, moves, or removes, the roles to terminate and to wake with their seats, models, and assignments, and the lifecycle hooks the step fires. `rp next --apply` does exactly what it states.
- **Pin** — An entry `<path>@<identity>` in a certification, recording the version of an input at the turn commit.
- **Pipeline** — A set of artifacts, each owned by one role. It is done when every artifact through the target phase exists and is not stale, no thread is open or escalated, and, when the target is the review, every review lane's approval is fresh.
- **Pipeline branch** — The branch a pipeline's commits land on: the **Pipeline branch format** convention applied to its slug, with `_<n>` appended for work on the pipeline once merged. Lane branches extend it.
- **Pipeline branch format** — The project convention giving the pipeline branch as a template over `<pipeline slug>`, defaulting to the slug itself.
- **Pipeline configuration** — `config.json` at the pipeline folder root, everything `rp` reads about the pipeline: the target phase; the base branch; the lanes and models the owner confirmed; the conventions the orchestrator copies verbatim at each run start, `.rp.local.md`'s overrides applied; the template of the commits `rp land` makes, as the Commit format convention has the orchestrator's commits read; and the owner's directions. Its presence makes a folder a pipeline.
- **Pipeline fact** — A fact a placeholder may name, valued for a role and its turn: `pipeline-slug`, the pipeline slug; `role`, the role's name; `profile`, its profile; `lane`, its lane, empty for a role without one; `worktree`, its worktree's absolute path; `branch`, its branch; and `merge-base`, the merge-base of its turn commit.
- **Pipeline slug** — The project convention deriving a pipeline's identifier from its issue, and that identifier: one path segment, a valid git ref, without `_`, naming the pipeline folder.
- **Pipelines folder root** — The project convention naming where pipeline folders live, defaulting to `.pipelines/`.
- **Production lane** — A named `spec-producer` or `design-doc-producer` lane with a model and an optional brief, which writes a candidate in its own branch and worktree, in parallel with the other lanes. It decides every question as any producer does, holds only its final reading, and opens no thread; the producer resolves where candidates differ when it consolidates them.
- **Proposal** — A direction or hypothesis to investigate, in the intent or a later `0-intent/proposal-<n>.md` with `target` and `origin`. Roles adopt or refute it with evidence; the owner's approval authorizes investigation, not its outcome.
- **Recipient** — The party a thread is addressed to: the owner of the artifact the thread is about, or `owner` for the intent.
- **Reported failure** — A result observed outside the run that contradicts the work — a command the owner ran, CI, a bug — recorded as given, with its evidence, in `0-intent/failure-<n>.md`. It carries no ruling: its targets' owners reproduce it and adopt or refute it.
- **Required inputs** — What an artifact must pin: the spec, the intent; the design doc, the spec; `notes.md`, the spec and the design doc; each, also every later input targeting it. A candidate pins its artifact's upstream artifacts only: the producer reads the later inputs targeting the artifact when it consolidates.
- **Resources** — The project convention describing what roles may run and use — environments, services, accounts, data, tools — and how, each an entry naming the profiles it serves.
- **Review base**, **review head** — The two commits a review lane's branch holds, built from the pipeline tip: the merge-base's tree on the merge-base, and the tip's tree on it, each with the pipelines folder reduced to the lane's view. The diff between them is the net change; the review head is the reviewer's turn commit.
- **Review lane** — One `reviewer`, with its brief when it has one, in its own branch and worktree, which `rp next --apply` builds from the pipeline tip as a review base and a review head: the reviewer sees the intent, its later inputs, the net change, and its own threads, and nothing else of the pipeline in the lane's tree or history. Without a configured lane, one lane named `default` runs. A review lane is approved when its latest review thread is `approved` and fresh; the implementation is approved when every lane is.
- **Review thread** — A thread a review lane opens to `implementer` about `implementation`. Closed `approved` and landed, its certification pins the intent and every later input at the review head its reviewer read, and records its approved commit: the pipeline-branch commit holding the approval, whose code is that review head's. It is stale when a required input changed, or when the tip's code differs from that commit's by anything other than clean merges of the base branch; in a clone that lacks that commit, it is no approval.
- **Role names** — The parties of a thread: `spec-producer`, `design-doc-producer`, `implementer`, `reviewer-<lane>`, and `owner`. A thread's `about` pairs with its recipient: `intent` with `owner`, `spec` with `spec-producer`, `design-doc` with `design-doc-producer`, `implementation` with `implementer`.
- **Seating** — Starting a role inside its assigned worktree, its branch checked out, by the active tool's mechanics (`tools/<tool>.md`).
- **Stale** — An artifact or approval with a required input that is unpinned or pinned at an identity that differs from the current one; an approval also when the code moved past it (see Review thread). Its owner responds by revising it.
- **Subagent model** — The model name a role delegates on, named in its assignment's Seat as the project writes it: the role's tool finds the model by it. The pipeline configuration sets it per profile and lane; without one, or when the tool finds no model, the role's subagents run on its own model.
- **Supporting folder** — The folder where a role keeps the screenshots, logs, command output, and transcripts its file cites: `1-spec/spec/`, `2-design-doc/design-doc/`, and `3-implementation/notes/` beside their artifacts; `<phase folder>/lanes/<lane>/<artifact>/` for a candidate. The reviewer has none: it pastes what it wants to share in its thread. It is not pipeline state.
- **Target** — What a later input addresses: one or more artifacts, whole or by clause id.
- **Target phase** — The highest phase a run executes before stopping.
- **Thread** — The conversation between two roles about one artifact, in one file, `threads/<n>-<opener>-<recipient>-<about>.md`, opened by a role that consumes the artifact. Its status is `open`; `approved` for a review thread or `resolved` for any other, once its findings are resolved; `withdrawn`; or, on a thread to `owner`, `escalated` and then `answered`. Each message ends its author's turn. A role writes each message's body, and `rp thread` writes the rest: the file name and number, the header, and each heading.
- **Turn commit** — The tip of a role's worktree when `rp next --apply` writes its assignment, named there and in the turn record. The role reads its materials at it, and landing certifies at it.
- **Turn record** — `rp`'s record, `turns.json` in the pipeline worktree's assignment folder, of each woken role's latest turn, and of the phases the last applied step woke, those complete when it was applied, and those its landings reported; `rp next --apply` writes it and `rp land` reads it.
- **Triage** — The orchestrator's entry for incoming work: it normalizes the request into an issue, scans the issue's pipelines, routes each statement, and confirms the runs that need it.
- **Variable** — A placeholder a project declares in its Variables convention, with a template over the pipeline facts, such as `agent` as `{pipeline-slug}-{role}`.
- **Wake** — Starting a role's turn: resuming its instance with a message, or spawning a new one.
- **Worktree** — A checkout of one branch. Triage creates the pipeline's and `rp next --apply` each lane's; the orchestrator seats roles in it.
- **Worktree folder root** — The project convention naming the folder under which one worktree is created per branch.
