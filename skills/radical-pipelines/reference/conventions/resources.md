# Resources

Resources are what a project makes available to its roles — environments, services, accounts, data, tools — and how to use them. A rule a role must satisfy is a guardrail, not a resource. Each resource has a name, the profiles it serves, and its text — what it is, how to reach it, what roles may do with it. A resource's text is written for roles; anything you, the orchestrator, must start, reset, or stop belongs in Lifecycle hooks.
