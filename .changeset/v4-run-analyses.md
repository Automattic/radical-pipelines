Tighten the roles after the analyses of finished runs. Inputs that exercise the same outcome are one acceptance criterion, and every reviewer message, approval included, records the outcome of each rule under Findings and Guardrails. Behavior intended use relies on and the intent does not ask to change stays as it is: a clause that changes it is a defect, never a risk. Every role reports each observation that bears against a claim it makes, with what explains it or that it is unexplained. A role cites committed evidence where it is and keeps in its supporting folder only the evidence it produces and copies of uncommitted evidence that will rotate. A role writes only in a thread it opens or one that awaits it; a closed thread is history. The spec producer reads its spec as the design doc's producer would. A role whose file `rp check` rejects is woken with the `INVALID` lines under a new **Malformed files** slot of its assignment and fixes them first. The files the orchestrator prepares for a role, such as the net change a reviewer reads, live beside the role's assignment in its worktree's git directory. On opencode, a running role is stopped with `POST /api/session/<id>/interrupt`, together with its subagents, and its session is kept as its transcript; on Claude Code, `TaskStop` keeps the transcript too. `rp stamp --pin` accepts paths relative to the pipeline folder as well as absolute ones, and reports a path that is not a file as unreadable, naming the path it tried.
