Add local, per-developer overrides of a project's conventions. A developer can now place a git-ignored `.rp.local.md` alongside the committed `.rp.md` to adjust a restricted subset of conventions — agent models, the health-monitoring cadence, and the Issues access-mechanism — for their own working copy or machine; everything else (shared-output conventions such as the commit format, artifact folder, pipeline slug, branch and worktree naming, the Issues tracker identity, and tool-forced command forms) stays committed and shared. Resolution is a local-wins-per-named-unit merge: where the local file names a unit its value is used (map-merging keyed lists like agent models so unnamed entries inherit), and where it is silent the committed value is inherited, so a local file only ever states the units it changes. The override is read from the project main checkout root and merged in memory on every load, never copied into a worktree, never committed, and never affects other contributors; a malformed or unreadable local file fails soft and is reported via a present-only batched summary rather than blocking the run. Overrides apply strictly after the committed conventions pass the required-completeness check, so a local file can never make a required convention read as missing or re-open setup. The capability ships as skill documentation — updates to the convention loader, setup flow, `SKILL.md`, and `README.md`, plus a new `local-overrides.md` reference doc that holds the full procedure.
