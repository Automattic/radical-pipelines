Define intended use, the measure every producer and reviewer applies to decide whether a case matters: a use the intent names, or one the project's documentation or code shows a consumer making. An input an artifact or the code merely admits, or a consumer no source shows, no longer justifies a requirement, a mechanism, or a finding. The same justification now applies to every case a spec requirement covers and every case a design decision rejects an alternative for. A spec names the inputs a term covers by what produces them instead of by a category. The design-doc and build-plan reviewers flag an adoption that builds for a case a clause demands but no intended use produces, instead of recording `Contradicts-input`.
