BREAKING: Bind each phase at its boundaries and leave the inside to the phase that observes it. The design doc states approaches and boundary contracts; a component's control flow, call sequences, names, literal values, and test cases are the build worker's, and what documentation states is the writer's. A decision states the component responsibilities and boundary contracts chosen, in a `Decision` field that replaces `Mechanism`. Its Verification names what each proof proves and at the cheapest boundary the intended consumer uses, never its inputs; a behavioral reason for rejecting an alternative names the proof that shows the difference, and the build worker records that proof failing against a bounded mutation of the rejected behavior. One `build-worker` profile replaces `build-worker-tdd`, `build-worker-edit`, and `build-worker-e2e` (project conventions version 5): a task owns every proof of the boundary it realizes, a flow belongs to the task that completes the last boundary it needs, and the task's `Type` and `Reference` fields are gone. Fidelity is judged as the same contracts, acceptance, or assigned files rather than the same text. Producers revise their own obligations; a mechanism, guard, or proof that serves no material obligation is a finding, and decisions and coverage findings alike justify a case's materiality by the input that produces it in intended use; acceptance criteria collectively verify each requirement's material outcomes; an assumption no material input produces is carried; disproportionate obligations escalate as contradictions; the build reviewer reports code that satisfies a clause the running software shows wrong as a contradiction of that clause. The document planner assigns files: one owner per file among unfinished tasks, files whose text must agree in one task or ordered by dependency, and the internal and external documentation the change needs, including files to create; a document task carries `Files`, `Traces to`, and `depends-on`; its `Goal`, `Surface`, `Audience`, `Acceptance`, `Sections`, and `Changes` fields are gone. The document worker reads its files and its dependencies' files in full, infers each passage's readers from its documentation context, states first what the change means for them, retains what they need for their work at the depth they need it, and keeps shared claims in agreement across files; the document reviewer derives the reader outcomes independently and judges the current documentation, corrective work superseding what it corrects; a documentation review targets an upstream artifact only for an obligation no accurate text satisfies. Under `experiment`, recorded observations support a failure's disposition and a causal claim needs discriminating evidence; a failure that does not reproduce on unchanged work is re-dispatched with its cause unestablished. A delta review rejects for a must-fix and no longer holds every case an earlier finding named; `prior-finding:` names the finding a new one continues. Across audited runs, upstream artifacts prescribed implementation and documentation content, every caught mistake became upstream precision, and no finding ever removed a mechanism; under the first version of these rules, review pressure moved to coverage of cases no intended use produces, proofs claimed to distinguish alternatives without having been run against them, and documentation that restated what its reader already assumes.
