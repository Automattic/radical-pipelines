BREAKING: Bind each phase at its boundaries and leave the inside to the phase that observes it. The design doc states approaches and boundary contracts; a component's control flow, call sequences, names, literal values, and test cases are the build worker's, and what documentation states is the writer's. Its Verification names what each proof proves and at which boundary, never its inputs, and distinguishes each decision from the alternatives it rejects. One `build-worker` profile replaces `build-worker-tdd`, `build-worker-edit`, and `build-worker-e2e` (project conventions version 5): a task owns every proof of the boundary it realizes, a flow belongs to the task that completes the last boundary it needs, and the task's `Type` and `Reference` fields are gone. The document task's `Sections` and `Changes` fields are gone; document tasks group by audience across surfaces; fidelity is judged as the same contracts, acceptance, or surfaces rather than the same text. Producers revise their own obligations; a mechanism, guard, or proof that serves no material obligation is a finding; an assumption no material input produces is carried; disproportionate obligations escalate as contradictions; the build reviewer reports code that satisfies a clause the running software shows wrong as a contradiction of that clause. A delta review rejects for a must-fix and no longer holds every case an earlier finding named; `prior-finding:` names the finding a new one continues. Across audited runs, upstream artifacts prescribed implementation and documentation content, every caught mistake became upstream precision, and no finding ever removed a mechanism.
