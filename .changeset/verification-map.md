Prove outcomes where the design doc places them instead of one test per acceptance bullet. The design doc gains a `## Verification` map naming, for each decision and acceptance criterion, its proof — an existing test, a new test at a named boundary, an e2e flow, the type system, or inspection — at the cheapest place the outcome is observable; a decision binds at the boundaries it names, and an edge case is named by the input that produces it and where. A plan task is the smallest change a reviewer can judge as coherent, points into the design doc through `Traces to`, and lists as `Acceptance` the outcomes it makes true, never facts about the implementation; a finding resting on an unreproduced observation is adopted as an assumption, and a corrective task states the obligation, never the fix. Build workers receive the spec and design doc as rationale, tests follow the classical school, a new test proves something no existing test proves, and the build review treats a test that proves nothing the map names as a finding. Tasks were being split per verifiable part and every acceptance bullet became a test assertion, so small changes yielded many tasks, tests duplicated across layers, mocks asserting calls, and handling for inputs nothing produces.
