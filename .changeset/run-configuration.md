BREAKING: Record the conventions each run reads in its pipeline configuration, keep `.rp.md` as prose, and have `rp` write each role's whole assignment.

`.rp.md` is prose a person reads and edits, at conventions version 7: its frontmatter is the one line `conventions: 7`, and the skill prescribes no form for the conventions below it. `Agents` becomes two conventions: **Lanes**, each profile's lanes and their briefs, and **Models**, each profile's and lane's model and subagent model. A tool's conventions sit in `.rp.md` itself: the orchestrator no longer reads a separate `.rp.<tool>.md` file. The new optional **Variables** declare placeholders. The lifecycle hooks `before-merging-lanes` and `after-merging-lanes` become `before-landing-lane` and `after-landing-lane`. Setup migrates a version-6 `.rp.md`: it rewrites the frontmatter, moves each `.rp.<tool>.md` into it, splits Agents, and offers Variables; apply the same changes to `.rp.local.md` by hand, which overrides `.rp.md`.

At every run start the orchestrator records the pipeline configuration, `config.json` at the pipeline folder root, which replaces `run-config.md`, from the conventions with `.rp.local.md`'s overrides applied: the target phase, the base branch, and the lanes and models the owner confirmed; the worktree folder root, commit format, guardrails, resources, and variables, copied verbatim; the template of the commits `rp land` makes, as the Commit format convention has the orchestrator's commits read; and the owner's directions for the run, one entry each. Editing `.rp.md` therefore changes no run under way, and a merged pipeline keeps the conventions it ran under. The run confirmation names, under each profile, the guardrails and resources the run will carry.

`rp` reads `config.json`, and never `.rp.md` or `.rp.local.md`. Before every turn, `rp next --apply` computes the role's turn from the frontier, fills its template, writes the assignment where the role reads it, and prints its path and the role's model. On a reviewer's later turn it also writes the diff the reviewer reads. A reviewer woken to fix malformed files it wrote gets a template of its own, which asks it to change only what each reason names and to keep every message, and an approval is certified at the commit its reviewer's last heading names. A malformed entry stops `rp check`, `rp next`, and `rp land`, naming the file and the entry, and they write nothing. The orchestrator copies no convention, path, or model into an assignment.

Model names travel as the project writes them, such as `sonnet`: the orchestrator resolves a role's model through its tool when it spawns it, and a role runs its subagents on the model its tool finds by its subagent model name, or on its own model when the tool finds none.

Guardrail, resource, commit-format, and brief texts may name pipeline facts in braces — `{pipeline-slug}`, `{role}`, `{profile}`, `{lane}`, `{worktree}`, `{branch}`, `{merge-base}` — and variables a project declares over them, such as `agent` as `{pipeline-slug}-{role}`, which `rp` expands for each role. A placeholder that names neither reaches the role as written, with those facts listed in its assignment.

A pipeline carries no format: a folder of the pipelines folder root is a pipeline when it holds `config.json`, and `rp pipelines` lists only such folders, without a format. It reads each pipeline's intent as `rp check` does, and stops on a malformed one, naming the intent and the reason. A pipeline started before this change is not continued: its folder is no pipeline to `rp`, so each review lane's tree keeps it, as it keeps a project's tooling, and work on its issue starts a new pipeline, whose slug names no folder in the pipelines folder root of the commit its branch starts from and whose pipeline branch does not exist yet. A new pipeline's `config.json` is committed with its intent, so its folder is a pipeline from its first commit.
